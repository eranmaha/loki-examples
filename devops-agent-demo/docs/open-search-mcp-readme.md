# OpenSearch MCP Server — Setup & Configuration

This document describes the OpenSearch MCP Server deployed as part of the DevOps Agent Demo project. The server enables the AWS DevOps Agent to query OpenSearch Serverless collections via the Model Context Protocol (MCP).

---

## Architecture Overview

```
DevOps Agent (Agent Space)
    │
    │  HTTPS (port 8080, X-API-Key auth)
    ▼
┌─────────────────────────────────┐
│  EC2 Instance (t4g.small/ARM64) │
│  ┌───────────────────────────┐  │
│  │  nginx (TLS termination)  │  │
│  │  port 8080 → 127.0.0.1   │  │
│  └───────────┬───────────────┘  │
│              │                   │
│  ┌───────────▼───────────────┐  │
│  │  opensearch-mcp-server-py │  │
│  │  Streamable HTTP :8081    │  │
│  └───────────┬───────────────┘  │
└──────────────┼──────────────────┘
               │  SigV4 (IAM role)
               ▼
    OpenSearch Serverless (AOSS)
    Collection: devops-agent-demo-logs
```

## MCP Server Package

### Source

The MCP server is the official AWS `opensearch-mcp-server-py` package:

```bash
pip install opensearch-mcp-server-py
```

- **PyPI:** https://pypi.org/project/opensearch-mcp-server-py/
- **GitHub:** https://github.com/opensearch-project/opensearch-mcp-server (Python implementation)

### Pre-build for Deployment

The package is pre-built for ARM64 (Graviton) and uploaded to S3 during Terraform apply:

```bash
pip install opensearch-mcp-server-py \
  -t .build/mcp-pkg/ \
  --platform manylinux2014_aarch64 \
  --platform any \
  --only-binary=:all: \
  --python-version 3.12 \
  --implementation cp
```

The resulting directory is zipped and uploaded to: `s3://<project-name>-assets-<account-id>/mcp-server-pkg.zip`

## Environment Variables

The MCP server process uses these environment variables:

| Variable | Value | Description |
|----------|-------|-------------|
| `OPENSEARCH_URL` | `https://<collection-id>.us-east-1.aoss.amazonaws.com` | OpenSearch Serverless collection endpoint |
| `OPENSEARCH_AUTH` | `iam` | Authentication method — uses EC2 instance role |
| `OPENSEARCH_IS_SERVERLESS` | `true` | Required for AOSS (vs managed OpenSearch) |
| `OPENSEARCH_REGION` | `us-east-1` | AWS region for SigV4 signing |
| `AWS_REGION` | `us-east-1` | Standard AWS SDK region |
| `AWS_DEFAULT_REGION` | `us-east-1` | Fallback region for boto3 |
| `PYTHONPATH` | `/opt/mcp-server` | Path to installed package |

## Systemd Service

```ini
[Unit]
Description=OpenSearch MCP Server
After=network.target

[Service]
Type=simple
Environment=OPENSEARCH_URL=<collection-endpoint>
Environment=OPENSEARCH_AUTH=iam
Environment=OPENSEARCH_IS_SERVERLESS=true
Environment=OPENSEARCH_REGION=us-east-1
Environment=AWS_REGION=us-east-1
Environment=AWS_DEFAULT_REGION=us-east-1
Environment=PYTHONPATH=/opt/mcp-server
ExecStart=/usr/bin/python3.12 -m mcp_server_opensearch --transport stream --port 8081 --host 127.0.0.1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

The server listens on `127.0.0.1:8081` (localhost only). All external traffic goes through nginx.

## Nginx Reverse Proxy (TLS + API Key Auth)

nginx listens on port 8080 with:
- Self-signed TLS certificate (generated per-deployment via Terraform `tls_self_signed_cert`)
- API key authentication via `X-API-Key` header
- Proxies to `http://127.0.0.1:8081`

```nginx
server {
    listen 8080 ssl;
    ssl_certificate /etc/nginx/ssl/mcp.crt;
    ssl_certificate_key /etc/nginx/ssl/mcp.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    location / {
        set $api_key_valid 0;
        if ($http_x_api_key = '<api-key>') {
            set $api_key_valid 1;
        }
        if ($api_key_valid = 0) {
            return 401;
        }
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_read_timeout 300s;
    }
}
```

## Security

### Network Access

- Security group allows inbound TCP 8080 from VPC CIDR only
- No public IP — accessible only within the VPC
- The DevOps Agent connects via private networking

### API Key

- Random 32-character password generated by Terraform (`random_password`)
- Stored in AWS Secrets Manager: `<project-name>-mcp-api-key`
- Passed to DevOps Agent via MCP server registration

### TLS Certificate

- Self-signed cert with IP SAN matching the instance's private IP
- Validity: 1 year (auto-generated on each deploy)
- The DevOps Agent needs the cert PEM for trust (provided as Terraform output)

### IAM Permissions

The MCP server EC2 role (`<project-name>-mcp-server-role`) has:

```json
{
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["aoss:APIAccessAll"],
      "Resource": "arn:aws:aoss:<region>:<account-id>:collection/*"
    },
    {
      "Effect": "Allow",
      "Action": ["logs:CreateLogGroup", "logs:CreateLogStream", "logs:PutLogEvents"],
      "Resource": "arn:aws:logs:<region>:<account-id>:*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::<project-name>-assets-<account-id>/*"
    }
  ]
}
```

Additionally, an AOSS data access policy grants the MCP server role `aoss:*` on the collection.

## DevOps Agent Registration

To register this MCP server with the DevOps Agent space:

1. **Private Connection:** Use the EC2 instance's private IP and TLS certificate
2. **MCP Server URL:** `https://<private-ip>:8080/mcp/`
3. **Authentication:** Header-based — `X-API-Key: <value from Secrets Manager>`
4. **TLS Certificate:** Paste the self-signed cert PEM (from Terraform output `mcp_server_tls_certificate`)

### Known Issue: Region Configuration

The DevOps Agent's MCP server association must have the AWS region (`us-east-1`) properly configured for SigV4 credential signing. Without this, the MCP server returns authentication errors when trying to query the OpenSearch collection. This is configured on the *server side* via environment variables, but the agent's *association* config must also support the credential chain correctly.

## Troubleshooting

### MCP server not responding
```bash
# SSM into the instance
aws ssm start-session --target <instance-id>

# Check service status
systemctl status mcp-server
journalctl -u mcp-server --no-pager -n 50

# Check nginx
systemctl status nginx
nginx -t
```

### Authentication errors from DevOps Agent
- Verify `AWS_REGION` / `OPENSEARCH_REGION` are set in the service environment
- Confirm the MCP server role is in the AOSS data access policy
- Check that the VPC endpoint is healthy and in the correct subnets

### 401 from nginx
- Confirm the API key in the DevOps Agent MCP registration matches the value in Secrets Manager
- Retrieve current key: `aws secretsmanager get-secret-value --secret-id <project-name>-mcp-api-key`
